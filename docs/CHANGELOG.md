## 1.58：关闭思考终于真的能关

「不思考」这一档以前是**什么都不发**。省略字段不等于关闭，它是让服务端用默认值，而服务端默认通常开着——所以这个开关从来没生效过。

现在按提供方发各自的字段：

- DeepSeek：`thinking: {"type": "disabled"}`
- ollama：`reasoning_effort: "none"`（顶层 `think: false` 只在原生 `/api/chat` 有效，走 `/v1` 兼容层不生效）

两条都在真机上验过。DeepSeek 那边连强制 `reasoning_effort: high` 都能被关闭压下去：单独 high 是 331 字思考，叠上关闭是 0。ollama 四连发思考长度全是 0。

顺带一个容易误会的地方：`deepseek-flash` **默认就不思考**，所以单看「不思考」这一档和默认没差别，真正有区别的是往上调——实测低 104 字、中 245 字、高 331 字。
## 1.57：状态键以角色卡为准，输入框对齐全

**状态键以角色卡为准。** 模型偶尔会给某个角色多写一行（卡上只有「好感度 / 内心想法」，它又冒出个「额外心情」），弹窗里会凭空多出一行，下次又对不上。现在代码层面只认卡上已有的键，多写的丢掉，模型漏填的格子用原值兜住，行序也按卡上顺序排，不会因为输出顺序变了而跳。

**输入框对齐全。**「我扮演的角色」原来两行、角色卡的「身份性格」两行、两个状态框五行，而且角色卡的状态框还单独缩了一号字，并排看着参差。现在四个框都是五行同一字号，实测高度都是 146px。

**格数上限回到 8 / 14 / 20**（初级 / 标准 / 高级）。之前我顺手抬成过 12 / 18 / 24，标准档不该动。档位说明文字也写清了各档格数。

这一版收口前做了一次全量回归：自检连跑 20 次全过，前端控制台无报错，拿真实模型跑一轮状态确实在更新（性欲值 30 → 35，三项全部回来）。
## 1.56：没写明的格子也要填，不留空

上一版我写反了，说「确实没内容就留空」。现在改成：卡上那几格都要填，键值里没写明的部分——表情、动作、情绪——也别空着，简单写一句就够，不用展开。

有键的仍按那个键的意思填：「当前好感度」填数值、「当前胸部状态」填胸部状况，各归各项，不串。每一格都要填满，某一格看不出具体内容就把表情/动作/情绪填进去；**不另开新键**，卡上有的就是全部。

仍然保留的约束：每格只填这一项本身，一般不超过三十字，不复述角色说过的话，不把动作写成一段叙述。

## 1.55：角色卡占位去掉性欲值，状态值不许复述台词

角色卡「当前状态」框里的示例文字还剩一行性欲值，删了。现在示例只有好感度和内心想法。

状态值改成短句：每一格只填这一项本身的内容，一般不超过三十字，**不复述角色说过的话**，也不把动作写成一段叙述——状态栏是让人扫一眼的，不是正文。键值里没写明的格子不要自己加，确实没什么可写就留空。

这条同时压在两个地方：独立那次状态更新（`STATE_SYSTEM`）和主提示词里按人那几行，两条路都按同一个口径写。
## 1.54：状态真的会自动更新了

上一版说修好了，其实没通。原因是**状态更新走的是 JSON**：让模型把十四行「键：值」塞进 JSON 字符串里，它会把内容写到一半改成对象数组，整段就成了非法 JSON —— 内容全对，一条都读不出来。再加上输入被截到 120 字、输出只允许 40 字，模型连后面那十几项都看不见。

现在整条链路改成纯文本，不再碰 JSON：

```
场景：地点=天台边缘｜在场=谭谈,孙雨晴｜离场=

孙雨晴
当前好感度：75/100
当前性欲值：35/100
```

模型照抄整组交回来，变了的换新值、没变的照抄原值。实测拿你那个会话跑了一轮：十四项全部收回，性欲值 30 → 35，地点和在场也对了。

顺带把输入和输出的截断都去掉了——那是模型「只改前两项」的直接原因。

另外给 JSON 解析加了一层修复：字符串里的裸换行现在能转义后重试，别的走 JSON 的地方也跟着受益。

状态框的例子收成两行（好感度、内心想法），不再把性欲值摆在占位文字里。
## 1.53：对话正文用中档

上一版把消息正文和旁白挂在大档上，跟按钮、输入框、顶栏标题同一号，正文反而没比周围大——看着别扭。现在对话区统一用中档：

```
小  12 / 13 / 15   ← 小 / 中 / 大
中  13.5 / 14.625 / 16.875
大  15.75 / 17.06 / 19.69
```

消息气泡、旁白、输入框、侧栏现在是同一个中档，大档留给标题和强调。三档下实测四处字号完全一致（小档 13px、中档 14.625px、大档 17.0625px）。

另外给 body 补了兜底字号（中档）：没单独指定的元素以前会继承根字号，那个是布局基准，比中档大一截。
## 1.52：删掉的事实还留在提示词里（面板骗人），字号整体上移

**事实删了但面板还显示**：上下文面板里那份「完整 system prompt」是上一轮生成时算出来的快照，删除只改了账本，没重算它，所以看着像没删掉。真正发给模型的是每次现算的，删掉的那条早就不进去了——问题只在面板显示。现在增删事实、改角色/状态/设定都会把快照重算一遍。

**字号整体上移一档**（比例不变，还是 rem 等比）：

```
小  12 / 13 / 15
中  13.5 / 14.625 / 16.875
大  15.75 / 17.06 / 19.69
```

上一版给的那组是 10.5 / 12 / 13.5 起，整体偏小。现在小档等于原来的中档，中档等于原来的大档，大档再往上。设置里还是选小 / 中 / 大，根字号 16 / 18 / 21 就是旋钮。
## 1.51：状态自动更新修好，字号再大一号

**状态不更新，三个原因叠在一起：**

提示词里把主角名写成了 AI 角色。你没填自己的状态格时，取「第一个有格的人」当主角名，于是提示词里出现「主角也要写，名字就用孙雨晴」——模型分不清谁是玩家，干脆不写按人那几行。现在主角名单独取，跟状态格有没有填无关。

档位上限卡在 8 格，你写了 14 项，后 6 项模型根本看不到。现在基础档 12、标准档 18、高级档 24。

弹窗只在点开那一刻构建，模型更新完状态，里面还是上一轮的数字。现在生成结束会重画，位置不跳。

顺带把解析放宽：模型经常把 `[[孙雨晴|好感度：…]]` 写成单层方括号，以前整行漏进正文，现在两种都认。

**字号加大一档**（绝对值，不随根字号推）：

```
小  13 / 15 / 17
中  15 / 17 / 19
大  18 / 20 / 23
```

根字号仍固定 16px，只给间距和栏宽用，所以字变大不会把布局一起撑变形。
## 1.50：字号收成三档

以前全站散着十几种字号，从 `.625rem` 到 `.9375rem` 各处写死，同一屏能数出七八个层级，而且说不清哪档管什么。现在只有三档：

**小**：注释、次要说明、微型控件。**中**：侧栏、按钮、表单、弹窗正文。**大**：消息正文、标题。

三档全部按 rem 走，跟着根字号变。设置 → 外观 → 字号 里选小 / 中 / 大（14 / 16 / 18px），整个界面同比缩放：侧栏、按钮、弹窗、消息、状态弹窗一起变。

写死 px 的漏网处已经清干净了，原来混在里面的 16px / 18px / 20px 都并进了三档。设置里的「特大」也去掉了——四档在那个尺度上区分不明显，三档反而清楚。

原来那对 `--msg-fs`（15px）和 `--ui-fs`（13.5px）并进了三档，侧栏和按钮现在比之前小半像素，肉眼看不出来，层级统一了。
## 1.49：状态弹窗改成规整的两列

上一版每行各自撑宽，短键右边留一点、长键右边留一点，值那一列的起点就成了一条参差的斜线。现在整块是一个网格：第一列的宽度取全表最长的那个键，键一律左对齐，值一律从同一条竖线开始，太长就在值那一列里折行。

弹窗也跟着加宽到 380px，够放最长那一行。
## 1.48：状态格写进角色卡，按人各一份

前两版把状态格挂在设定里全局一份，等于逼所有角色套同一个模板——男性角色身上挂「子宫状态」当然很怪。现在格子在**每个角色自己的「当前状态」框**里。

角色卡的「当前状态」框加大成多行，直接照「键：值」一行一项往里写：

```
［当前好感度：75/100］
［当前性欲值：30/100］
［子宫状态：未被开发，因涨奶刺激轻微发热］
```

写进去的就是这个角色要维护的那几格，模型每轮在原值上改。点角色名弹出的窗里一项一行显示：模型这一轮更新过的用新值，没提到的沿用你写的。主角也有这么一个框（在「我扮演的角色」下面），一样写、一样看。

设定里那个全局框删掉了；顶栏也不再堆一竖排格子，那里只留全场共用的处境（地点、时间、关系、目标）。

**按档位限数**：这些格每轮都要重抄一遍，给多了小模型会漏项、或者干脆缩成一句话交差。基础档每个角色最多 8 项，标准档 14，高级档 20，超出部分模型看不到——角色卡下面会写明这一档是几项。

顺带修掉一个会吃掉你写的状态的问题：模型每轮会写一句「变化」，那句话以前会把整组键值对盖掉。现在有键值对的车不碰，只记进历史。角色卡的状态框原来还截在 200 字，十四行根本装不下，一并放开。
## 1.47：状态栏的格子按人分开

上一版把这些格子记成整局共用的一份，谁也说不清那到底是谁的好感度。现在一人一行：

```
[[孙雨晴|好感度：75/100|子宫状态：未开发]]
[[谭谈|好感度：40/100|当前性欲值：10/100]]
```

第一段是人名，后面接他自己的那一组。主角也要写，名字用你在角色里填的那个称呼——提示词里会把名字写死进去，不用你记。

顶栏的状态栏按人分成一小块一小块，名字在上、格子在下，主角那一块高亮。点某个角色的名字，弹层里除了原来的「状况」「物品」，也多出他自己的这些格子。

场景那一行（地点、时间、在场）还是老样子，两条互不干扰：场景行认字段名，人名行认名字，解析时各归各位。
## 1.46：成人向的要求写全了

上一版只有一句「写足过程和身体反应」，把细度定了，但**怎么写**、**写到哪儿收**都还是空的。现在拆成四段：

肢体接触、衣物褪去、生理反应、心理快感都要细致刻画，不用「一夜过去」带过；感官落在具体的触感（温度、汗湿、摩擦）和声音（喘息、水声、布料撕裂）上，双方的交锋与拉扯要写，配合、抵抗、失控都是戏；性要贴着两个人的性格和当前关系走——强迫、偷情还是深爱，写法不一样，事后要有温存、疲惫或纠缠，不能一到高潮就停笔；暴力和脏话按角色性格来，粗粝感和压迫感不磨平。
## 1.45：状态栏可以自己加格子

以前状态栏只认固定的那几项：在场、离场、地点、时间、关系、物品、目标、事实。别的写法就算模型写出来了，解析器也只认白名单键，多出来的格子整格丢掉、挤回正文里。

现在「设定」里多了一栏「状态栏里额外要记的格子」，一行一个名字。写进去什么，每轮就要求模型给出那一项的当前值，跟默认那几项挤在同一行里。界面上单独列成多行，一行一项，长内容自己折行——好感度、当前性欲值、内衣、子宫状态、内心渴望这类都能挂上去。

存的时候故事和会话各存一份：在故事里改，之后开的每一局都继承；在单局设定里改，只影响那一局。

没填就一个字都不加，跟以前完全一样。
## 1.44：成人向的尺度说清楚了

选「成人向」时那段要求补全了：不遮掩，细致入微地刻画肢体接触、生理反应与心理快感，可跨越常规界限。

原来的说法是「写足过程和身体反应」，只在反对一笔带过；写到多细没说。现在两头都定了。
## 1.43：一轮全项目体检

后端、前端、可删减项三个方向并行审了一遍，修掉十处真问题，删掉一批死重量。

**会丢数据或让功能失效的**

清空对话之后压缩游标还停在旧位置，头几条新消息静默不进上下文，压缩也永远报「不用压」。

模型自动重试时，循环变量把调用方指定的思考档位盖掉了——重试实际上是把上一段的思考正文当成档位发出去，模型不吐思考时又退化成空串。档位在重试里等于丢失。

还原备份是全库覆写，却没拦生成中的会话，那一轮收尾时会把刚还原的内容盖掉一半。

上一份设定里「单项重生成」留下的撤销点，切到另一份还亮着。点一下就把旧值写进这次的表单，一保存就落盘。

**两局同时跑才会撞见的**

首字耗时可能记到别人头上（挑的是「第一条还没记过的」），并发写入还会把那个字典改坏，整轮直接报「生成中断」。

流式响应失败分支从不关连接，重试一次漏一个，句柄一路涨。

**能直接看见的**

连点两个会话，先发出去的请求后回来，会把界面覆盖成上一个会话：标题、消息、侧栏高亮全指向别人那一局。

往上翻历史时，每次重绘都被拽回底部——那层「本来就贴底才跟着滚」的判断写在清空之后，那时位置已经是 0，判断永远成立。

切走会话不停朗读，也不停「等它写完」的轮询：声音接着念上一局，而暂停按钮已经随着界面重建消失了。

运行期创建的按钮（消息工具条、侧栏条目、搜索结果）点完会抢走输入框焦点，之后按 Enter 不再发送——原来的处理只绑了启动那一刻已经存在的按钮。

**删掉的**

两个遗留探针脚本（其中一个会对真实数据目录直接改文件名，误跑会毁数据）、两个没人调用的前端函数、`lt.py` 里二十多个没人引用的转发，以及账本取值函数重复的一份实现——那份默认写死 12 条，和按档位取的另一份已经不一致，而自检正好测的是没人用的那份。

**这轮没动的**

审计还列了十几条，都有道理但代价不小：状态刷新在会话锁里做同步模型调用、流式渲染每个增量都全量重建 DOM、三处重复的原子写、六处文档与代码脱节。一次改太多不好收，留到下次。
## 1.42：叙事风格与内容尺度分开

上一版把所有东西塞进一个「写作风格」里，其实混了两个不同的问题：怎么写，和能写到哪。现在拆成两项。

**叙事风格**决定语气和排版节奏，四档：网文通俗（直白、节奏快、痛快）、轻小说（对白占大头、心理活动多、语气轻快）、古典章回（半文半白、重环境描写、说书腔）、散文文艺（重情绪和画面、情节让位给氛围）。

**内容尺度**决定能写到哪，两档：全年龄（亲密场面靠留白带过，暴力不渲染细节）、成人向（性场面写足过程和身体反应，暴力和粗口按剧情需要写）。

两项互不干扰：选「古典章回 + 成人向」就得到半文半白又写足场面的东西，不会像以前那样选了一个就把另一个覆盖掉。尺度默认全年龄。

风格那一栏还留了输入框，四个档都不合适时可以自己写一个类型名。
## 1.41：写作风格改成按钮

1.40 那个写作风格只有一个输入框，得自己先知道有哪些类型、名字怎么写。现在是一排按钮：不指定、言情小说、轻小说、通俗小说、色情小说、武侠、科幻、悬疑推理、恐怖、古典章回、散文——点一下就行，选中的会亮。

想用自己的词，直接在下面那行输入框里写；写的东西正好撞上某个预设，对应的按钮也会跟着亮。按钮按文字宽度排、自动换行，不会被压成两个字宽。
## 1.40：写作风格

设定的「写作」里多了一项。下拉里十个现成的——言情小说、轻小说、通俗小说、色情小说、武侠、科幻、悬疑推理、恐怖、古典章回、散文——也可以自己填一句，比如「日系轻小说」「民国谍战」。

选的不是标签，是一段写法要求。每张卡给的是「怎么写」不是「像什么」：言情强调情绪落在具体的动作和物件上、信息主要靠对话给；悬疑强调线索摆在明面上但不点破；色情强调过程和身体反应、在场的每个人都要写到。只丢一个类型名过去，模型只会写出一团模糊印象；给具体手法，文风才真的会动。

留空就是不额外规定，提示词里一个字都不加。这项排在语言之后、人设和背景之前——排到后面会被具体情节的要求盖过去，等于白设。
## 1.39：点了停止，后端还在写

三件事其实是一个毛病。

点停止之后，前端只是断开了自己这一头的连接，后端那条生成还在一路读到模型说完。于是：界面上看着停了，实际那一轮还在跑；刷新页面看到「AI 正在写这一轮」，只能等它结束；而它结束时又走了一遍「用户已喊停」的收尾，把**完整的一段**当成半截存进对话。你点了停止，回头却多出一整轮，内容还和前面撞。

现在停止会在读到下一个字时立刻生效：断开上游连接、线程收工、生成状态在半秒内放开，存下来的只有真正显示出来的那半截。

同一处带出两个也修了。一是自动重试时，上一次尝试吐出来的字没清零，喊停后存下的「半截」是两次尝试首尾相接，同一段内容重复两遍。二是半截存盘时正文里带着 `【旁白】` 这类格式标记，和正常写完的格式不一样，续写时它会被当成上一轮的台词喂回模型。
## 1.38：角色卡三格并排

角色卡上的名字框原来单独占一行，音色和语气在下面一行。四张卡叠起来，整个面板被拉得很长，改一遍设定要来回滚。现在名字、音色、语气并排，名字稍宽一点——下拉里的选项文字短，名字要写得下。

另有一条自检修正：费用累加的断言把价格写死成 1.0 元。国内厂商有峰谷价，工作日 9—12 点、14—18 点翻倍，所以这条断言上午跑是绿的、下午跑就红，跟代码对不对没关系。改成按当前时段算期望值，另加一条「两个币种必须不同」，免得 estimate_cost 哪天退化成恒返回 0 时这条跟着假绿。
## 1.37：还原别再把自己删了

1.36 改了还原的顺序——先打底再读包，为了躲开同秒撞名。这个顺序带出一个新问题：
打底那一步会顺手按份数裁剪，而裁剪从旧往新删。份数调到 1 时，被删的正好是你正准备
还原的那一份，随后读包就报找不到文件。默认 30 份不会直接失败，但每次还原都吃掉一份
配额——试错还原十几次，早期那几份真备份就被挤出去了，界面还不会告诉你。

现在打底时不裁，整个还原做完再裁，该收敛的份数照旧收敛。

顺带修掉一个自己埋的：上一版给备份列表加的「同秒按序号排」，正则里 `\d` 写成了 `d`，
`\.` 也没转义，等于从来没匹配上。排序静默退化成只按秒级修改时间，同一秒的几个包谁在
前谁在后取决于目录列出的先后。现在真能解析出 `-2`、`-3`，同秒里序号大的排前面。

自检连跑 20 次全绿。
## 1.36：备份撞名

备份包的名字只精确到秒。同一秒里连点两次「立即备份」，第二份会把第一份截断重写——
你以为存了两份，实际只有一份。还原时更糟：还原前会自动打一张 before-restore 的底，
如果它恰好和正在读的那个包同名，写底那一步就把句柄下的文件换掉了，后面读到一半抛
`BadZipFile`，接口返回 500。双击还原按钮就能撞上：第一下正常，第二下报错，而且那个
备份包已经被写坏。

现在撞名就加序号（`-2`、`-3`），包名唯一。还原改成先校验包能不能读、再留底、留底之后
才开包，两条路都堵上。备份列表的排序也补了次级键——时间戳只到秒时，「最新的」原来会
在同一秒的几个包之间来回跳。

还原接口补了兜底：包里有文件读不出来时回 JSON 报错，不再是 Flask 的 HTML 错误页
（前端读不到 error 字段，界面上就是「点了没反应」）。

自检连跑 20 次全绿。这一条是版本自己抓出来的：上一版新加的备份往返断言会真去还原，
还原真会崩，只是五次里才响一次。
## 1.35：四条收尾

上一版修「回滚设定不吃聊天记录」时，把整个 `characters` 当成聊出来的进度排掉了。
角色卡里名字、身份、音色、语气是在设定面板里填的，只有 `state` 和 `history` 是模型
一路写下来的。整个键排掉，等于拍设定快照、改坏、回滚之后角色卡一动不动——同一个
故障从消息挪到了角色卡上，而当时那条断言只查消息条数，所以一直是绿的。

现在角色卡按名字逐条合并：名字对不上（改过名、或者整张表被换过）就按位置认，设定
从快照来，`state` 和 `history` 留在现在。改过名的角色不会因为回滚丢掉一路聊出来的状态。

生图工作流那份文件上一版只是从版本库里摘出去，`.bak` 还在跟踪，而每次导入都会写
`.bak`——脏的从主文件变成备份文件，等于没解决。而且 `.bak` 是「上一次用过的」，不是
出厂值，导入两次就面目全非。现在拆成两个角色：`moss_workflow_api.default.json` 入库、
只读、运行时绝不改写，主文件和 `.bak` 都忽略，加载顺序是 主文件 → `.bak` → 出厂默认。

还有两处小的。设置写盘失败的标记原来先读先清、再判断这次请求该不该报，前端冷启动
并发发的两条 GET 会把它读走，那次失败的写请求照样返回 200；现在 GET 和 SSE 一律不碰
这个标记。快照目录的自清理原来只看「有没有对应会话文件」，会话被临时搬走（手动备份、
资源管理器里剪切）时，当天那次扫描会把快照全删掉，还留不下痕迹；现在见不到至少两个
会话就当天不扫。

这四条都做了变异验证：把修复改回去，对应断言立刻变红。
## 1.34：把 P3 收拾干净

这一批大多是卫生问题，没有崩，但都是会慢慢变坏的那种。

**五千字的标题原样落盘**。标题只去两个地方：侧栏一行，和生图提示词里给没写世界观时
补位。给多长都不会显示得更完整，只会把文件撑大、把画面带偏。现在落盘时统一截到 60 字，
不管从哪条路进来（建会话、改设定、自动起名、分支、导入）。

**语音那一段设置多了一个没闭合的 `div`**，浏览器只能自己猜边界，后面的兄弟节点被吞进
去。删掉那一个多余的标签，整个模板的 `div` 开始和结束终于相等——这条现在有断言盯着。

**日志只按天清，不按大小封顶**，而且清理只在进程第一次写日志时跑一次，应用开着不关就
再也不清了。现在单文件撞 8 MB 滚一代（旧内容留一份 `.1`），过期清理改成每小时跑。

**会话删了，它的快照目录永远留着**，实测攒了 83 个、3 MB 多。现在每天扫一次，把没有
对应会话的目录收掉。

**导出的 Markdown 响应头里有两个 `charset=utf-8`**——`mimetype` 里自己写了一个，Flask
又补一个。去掉重复的那个。

**上下文面板的读写耗时是全进程最后一次，不是这一局的**。手机那边动一下别的会话，电脑上
看到的就是别人那次。改成按会话各记一份。

**币种符号曾经只在前端硬编码**（`USD ? '$' : '¥'`），后端那张表没人用。往 `CURRENCIES`
里加第三种币，后端读得出来、界面一律显示人民币符号——这是这一批里唯一会导致错数据的。
现在符号表由后端随配置一起给。

顺带清掉四张全库没人引用的标签表，把 `start.ps1` 的 Python 检查从「大版本是 3」改成
「至少 3.10」（文案早就这么写了，代码只认大版本，装个 3.9 照样放行），补了一个
`requirements.lock.txt` 记实测通过的精确版本，`moss_workflow_api.json` 不再进版本库
（导入工作流会改写它，一改仓库就脏；出厂默认留在 `.bak` 里，找不到主文件时回退到它）。

文档也跟着对齐了：语音那节还停在「`vox serve` + HTTP」，实际早就换成管道常驻进程；
`cover_history` 写的是字符串数组，代码里是对象数组；自检耗时写着「几十秒」，实测 2.3 秒。

断言补了三条真的：备份往返（打包 → 改坏 → 还原 → 内容退回去，这是唯一的数据恢复路径，
之前零覆盖）、版本号漂移（README、CHANGELOG 必须和 `VERSION` 对上，这版我自己就先改了
文档后改版本号）、模板 `div` 配平。
## 1.33：剩下的六条，连手机那条也补上

接着上一版把 P2 清完。这一批里有两条会让人真用不下去，其余是隐患和工程账。

**封面生成会永久卡死一份故事**。收尾那几步（缩略图、写盘）以前在 `try` 外面，抛个
`OSError` 线程就带着「正在生成」死掉；而再次点生成时看到「正在生成」就直接返回旧任务，
于是这份故事的封面再也生不出来，只能重启应用。现在整段都包住，另外给状态加了个过期
时间：线程真卡住不返回，过了时限也允许重新提交。

**手机连不进来，而且启动日志看着一切正常**。局域网地址只在启动那一刻算一次，那时网卡
要还没起来（开机自启、Wi-Fi 正重连），白名单里就只剩本机回环地址，手机从此 400 到底。
现在取地址失败时退一步枚举网卡；再开一个轻线程定期重算，地址变了就补进白名单，插回
网线就能连，不用重启。启动时真取不到也会明说一句，不再静默跳过。

**自己导入的工作流看着能用，一跑就炸**。校验以前只看「五个节点号在不在、有没有
`class_type`」，可生成时是直接往节点的 `inputs` 里写提示词和尺寸的——没有 `inputs` 也
能通过校验，真跑才报错。现在连 `inputs` 和它里面那几个字段一起验，导入时就告诉你是
哪个节点缺什么。

**刷侧栏把整个会话库重新解析一遍**，而故事列表为了数「每个故事开过几局」又解析一遍。
会话文件没动过就该直接用上次的摘要——现在按修改时间加大小做缓存，动过才重读。

**自检往真实日志里灌假数据**。每次跑检查都不带日志目录，于是 `gpt-4o`、百万 token 这些
假事件全写进了真实记录，出事复盘时 grep 到的全是噪声。改成写进临时目录，跑完就扔。

**绿灯不一定真绿**。报告里点出有一批断言只是检查源码里有没有某段文字，改错了照样过。
这次新加的断言一律验行为，顺手把两条最容易骗人的换了：Host 白名单改成真发两个请求
（本机该通、陌生域名该被挡）；生图收尾改成打桩让写盘抛异常，看状态是不是真变成失败。
两条都拿「改回旧写法」反向验过，改回去就红。
## 1.32：出错的时候不再一声不吭

按 `HEALTH_REPORT.md` 那份体检报告逐条核过，先修影响最大的七条。它们看着分散，其实
是同一种病：出了问题不吭声，事后也没痕迹，用户只看到「怎么又不对了」。

**语音设置一保存就静默失效**。`rp/speech.py` 里那把启动锁是不可重入的，而启动失败的
分支上会回头再抢同一把锁——同一个线程等自己，永久卡死。卡住之后设置存不进去，朗读
再也没声，重启才好。换成可重入锁，这处死锁就从根上没了。

**改完设定点回滚，聊天记录跟着陪葬**。快照存的是整份会话，回滚时整份写回去，拍快照
之后聊的每一轮都被吃掉了，界面还只说一句「已回滚」。现在快照认得来路：改设定前自动
拍的那张只还原设定（人设、世界、规则、开局、词条），聊天记录、轮次、角色状态、事实账
本一律保留；手动存档点仍然是整份还原，那是存档点该有的语义。

**手填的世界设定会被悄悄删掉**。事实账本有条 40 条的滚动上限，超了就从头砍。可是手填
的条目和最老自动条目挤在同一个队里，聊得久了，你亲手写的设定先被砍光——而设定界面
上写着上限 200。现在来源分开算：自动记账按 40 条滚动，手填按 200 条滚动，井水不犯
河水。

**恢复备份可能把会话写成半截**。这是全项目唯一一处不做原子替换的写盘：中途崩一次，
会话文件就是半截 JSON，读不出来，界面上就是「这一局没了」。改成先写临时文件再替换，
和别处一致。

**生成到一半会话被删，正文凭空消失**。以前这里退回空值继续报「完成」，用户以为存住
了。现在明确报错：这一局在生成过程中被删掉了，写的内容没能存下。

**设置没存住却弹「已保存」**。写盘失败以前只往日志里留一行。现在失败会跟着响应一起
回去，界面直接报错，不会再让你以为存住了。顺带：这处兜底自己先犯过一次错——在
`after_request` 里返回元组，Flask 会当场砸成 TypeError，比原来的静默失败还糟，已经
改成返回真正的响应对象。

**朗读失败只在控制台说一声**。用户那边的感受就是「点了没反应」。现在会弹一次提示，
连着失败不会刷屏，念出下一句重新计数。

这七条都补了会真失败的断言，其中锁那条拿「改回不可重入」反向验过：改回去就红。
## 1.31：刷新不再把写到一半的话弄丢

停止、重发、刷新三个动作以前都缠在同一根线上：浏览器还连着没有。连着就写，断了就当用户不要了。
于是刷新等于取消，停止等于整段丢掉，回来一看按钮都没了。

**刷新页面不再打断生成**。生成挪到后台线程，浏览器那头只负责转播。关掉页面、切到别的会话、
手机锁屏，那一轮照样写完、照样落盘，回来自动就在那儿。以前界面文案写着「页面刷新不会打断它」，
实现却正好相反，现在两边对上了。

**停止是真的喊停，不是断网**。新增 `/api/chat/stop`：点「停止」先告诉后端「不要了」，再断开连接，
后端这才分得清「用户不看了」和「用户不要了」。停下来那一刻已经写出来的字存成正式消息，标一个
「未写完」，点 ▶ 就能接着往下续，不用整段重来。

**停止之后按钮一定在**。这是三个毛病叠在一起：半截内容只活在 DOM 里，而生成结束会重绘整张列表，
它不在消息数组里，于是连按钮一起被抹掉；那条本该在重绘后校准界面的代码写的是 `state.session === s`，
可刷新函数已经把 `state.session` 换成了新对象，这个比较永远为假，校准一次都没执行过；操作栏本身又是
悬停才出现，点完停止鼠标停在下面输入区，那排按钮等于不存在。现在半截落盘、重绘真的触发、最新一条的
操作栏常驻显示（悬停仍然加亮）。

**「正在写」提示也栽在同一个坑里**。它靠一个计时器判断「已经挂过了」，可重绘会把节点连提示一起清掉，
第二次重绘起就再也挂不回去。刷新后既没有「正在写」也没有「没答上」，屏幕上光秃秃一条用户消息。
现在认节点不认计时器。

顺带：停止存下的半截会过一遍解析，旁白归旁白、台词归台词，不再整段挂在同一个角色名下。
## 1.30：一人一卡，声音各归各的

这一版四件事：角色名和语音的坑填了，设置里的表格能真正保存，手机能用了。

**名字后面的括注不再是另一个人**。模型爱写 `【叶岩（在篮球场）】` 交代人在哪儿，以前照抄，
角色表里就多出一张「叶岩（在篮球场）」的卡，跟「叶岩」并列，删掉一张另一张还在。现在读进来
就把结尾的括注剥掉，撞名的合并成一张，原有设定留着。老会话打开就自动修好，不用手动清。

**语音念不出来了的根子**。worker 只把 stdout 钉成 UTF-8，stdin 还在按系统代码页解。中文进去
变成乱码，vox 报的却是 `feed(): incompatible function arguments`——一句跟编码完全无关的话。
现在两个方向都钉死，跟机器的语言设置无关了。另外 worker 崩了会把栈落到 `_vox_worker.err`，
以前 stderr 直接丢掉，出问题只能猜。

**设置里的表能存住了**。单价和说话风格都改成表格。删掉的单价以前会自己长回来，因为默认表还
记着它；现在记一份删除名单，删了就是删了。

**新对话窗口**：宽了一档，每条带封面缩略图，每页 10 条正好填满，列表空着也不塌。

**手机**。三处溢出：顶栏那条「按钮不许缩」的规则误伤了设置里的模型下拉，把刷新按钮顶出屏幕；
备份那一行窄屏放不下；单列时新对话列表的长标题会把列撑破，省略号失效。都修了。

顺带：角色卡和主角可以各自挑音色和说话风格，不用再为了换个声音去改全局表。

## 1.26：本机朗读，边生成边读

加了两件事：把本机跑的生图接进设置，再让模型写的话能念出来。

**生图**：ComfyUI 地址和超时进了设置（设置 → 模型 → 生图）。以前只能改 `LT_COMFY` 环境变量，
换台机器就得重开终端。留空仍然回退到环境变量，所以老用法不受影响。

**语音**：走 [voco](https://pypi.org/project/voco/)。它把运行时和模型拆开，`pip install voco`
之后装哪个模型插件就用哪个，**换声音只改设置里的插件名**。目前官方插件是 `voco-kokoro`。

两种用法：

- 边生成边读：模型吐一句念一句，够一句（句末标点且不少于 6 字）就送去念，念完接下一句。
  生成结束或中断时剩下的尾巴也念完。开关在设置 → 模型 → 语音
- 手动朗读：每条气泡右上角一个 🔊，点它整段一次请求

代码块和 `[[状态标记]]` 跳过不念，不然会念出一串星号。两种用法共用一个播放通道，
所以不会几段声音叠在一起。

## 1.14：重发不再点空，用量只算这一局

**重发偶尔没反应**，非得刷新页面。那条路上一共有三处「条件不满足就静默 return」：没选中
对话、上一轮还在生成、DOM 上的序号对不上消息记录。现在都会说一句（「上一轮还在生成，
等它写完再重发」「刷新一下页面再试」），至少知道卡在哪。另外重发会删掉这句之后的所有
回复，后面还有内容时先问一句再动手。

**累计 token 只算这一局**。以前读的是全局累计，别的会话的用量也加在里面。现在按会话
分开记，面板显示的就是这一局烧掉的量。

**「顾清岚及警员」不会再被当成一个人**。连接词（和、与、跟、及）两边的名字都够两个字，
说明那是两个人被并成了一条，不再建卡；只拆出单字的（「林和平」被「和」拆成「林」「平」）
仍然当一个人看。

**前情提要挪到被折叠的那截消息后面**，一眼看出它替代的是哪一段。**「🧭 当前状态」卡片
删掉**——底部状态栏已经有了。

**破坏性操作都有二次确认**：清空对话、删会话、删故事、删备份、还原备份、删提供方、
重置设置、回滚快照、删账本条目、删封面，加上这轮补的重发和手动压缩。

## 1.13：压缩过的原文一条都没丢

**被压缩的对话，实际数据全在**。压缩做的是把 `compressed_upto` 游标往前推——那批消息
不再进上下文（由摘要代替），但原文一直躺在会话文件里：界面上照样往回翻，导出、存档、
重写也都还是完整的。每次压缩之前还会另存一个存档点。

**修了「已折叠」虚报**。那个数原来是累加出来的，可重写会清摘要、把游标往回退甚至清零，
于是同一批消息被反复计数——383 条的会话报成折叠了 3393 条，看着像丢了几千条。现在直接
按游标算，不会再错。历史记录里的虚高值一并校正过，原始文件备份在 `backups/`。

## 1.12：同一件事只记一条

账本里常出现这种：第 0 轮记「丈夫出差第7天，还有23天」，第 15 轮又记「丈夫出差第7天」。
两条的字集合重合度只有 0.63，原来那道 0.7 的相似度闸门根本碰不到，于是并排留下两条。

它们是**包含关系**——后一条是前一条的前缀。现在按子串判定：一条被另一条完整包含，
就算同一件事。留信息全的那条；后来的更详细就升级掉旧的简写，一样长就留新的说法，
你手填的优先留下。归一化也改成连标点一起去，「报警电话已接通。」和「报警电话已接通」
不会再算两条。

## 1.11：删条目前先问一句

账本每条的 × 改成两段式：第一下把按钮换成红色的「确定删除」，再点一下才真删，
三秒不点自己收回。一行只有一个 ×，手指一滑就删掉一条设定，代价不对等。

## 1.10：账本能自己改

**上下文面板里的事实账本可以删、可以手填了**。以前那是只读的——模型记错了、
记漏了，你只能等它下一轮自己想起来。现在每条右边有个 ×，点掉就从账本里消失，
下一轮不再注入；底下多一行输入框，写一句就记进去，跟模型自己记的走同一本账。

删的时候按「轮次 + 原文」定位，不是按下标——模型随时往里记账，两次渲染之间
下标会漂，按下标删容易误伤。手填的条目挂 manual 标记，条目数和自动记的分开算：
自动记账 40 条封顶，手填的放宽到 200，免得被你塞进去的设定被很快挤掉。

**同一句不会再记两遍**。以前模型重复声明一条已经记过的事实时，旧的那条被标成
「已失效」，同时又抄了一份新的——面板里就是同一句话并排两条。现在一字不差的直接
把原条目复活、轮次刷新，账本不增长；已经攒下的那种副本会在下一次记账时一并清掉。
换了说法的（「不许再犯」和「明确不许再犯」）仍算两条，旧的标失效、注入只用新的，
因为它确实换了个意思。面板也改成只列现行条目，失效的不再混进来。

**单项重写的框回到中间**。点字段旁边那个 ✦ AI，弹出来的输入框以前贴在面板最底下——
它复用了「完善整份设定」那层的定位，而那层是故意贴着底部输入框的。现在给它单独一条
规则：四边留白加 auto 边距，垂直水平都居中。

**上下文面板的用量与底层诊断并成一块**。以前上面是上轮用量和耗时，下面另有一个折起来的
「底层诊断」，看得先展开一次。现在消息数、压缩次数、写盘读盘、缓存、费用全接在同一块里，
一路读到底。顺带删掉重复的「前情提要」行——系统提示词构成里的「前情」就是它，两处报的
数还不一样（475 和 488）。

## 1.00：设定不再自言自语

**设定生成不再把思考过程当正文存下来**。表现是：生成世界观或角色卡，拿到的是一段
「用户要求写 240~360 字角色卡……任务说……不过这似乎是必须满足的要求……」。

根子不在提示词，在预算。推理模型先写思考再写正文，两者共用一个 `max_tokens`。
设定生成原来只给 800，思考照样能花掉一千多字——正文字数是零。而代码里有一句
「正文为空就拿 reasoning 顶上」的兜底，于是那段草稿被当成设定存了下来。字数上调之后
思考跟着变长，这个坑才露出来。

现在的做法：正文为空就是失败，退回重试，绝不拿思考充数；设定生成的预算提到 8000，
思考之后还有余量写正文；真拿不到就报错让你重试，而不是塞一段垃圾进设定。实测同一份
角色卡，思考 910 字、正文 494 字、七秒出头。

**还有两道剥与查**。带「故事背景：」这类标题的分析直接剥掉，取标题后面那段；正文里
出现「任务说」「本次任务」「用户说」这种只可能出现在分析里的词，判失败重试。

**三类设定的字数各设一组**。角色卡、世界观、开场白篇幅本来就不一样：一张卡受注入上限
限制，写超了会被截断；世界观要铺时代地点规则与禁忌；开场白要留出第一段互动的余地。
原来三段共用一个区间。换档位时三组自动填好——和你熟悉的上下文上限一样，手改只在当前
档位有效。初级档是 120~180 / 200~300 / 160~240，标准档翻倍，高级档再放大。

**故事列表和对话列表对齐**。故事那条原来用网格布局、也没有条目间距，每条比对话矮 4px，
每页能多塞一条，切换视图时看着高矮不一。

**字数下限填得比上限高时，上限被抬上去**。原来只有旁白和角色言行两组有这个兜底，
新增的三组没有，填反了提示词里会写出「800~60 字」。

## 0.90：字数按你说的算

**上下文改成按 token 计量**。原来面板和压缩线算的是字数，可模型吃的是 token，
两者差着一倍多；到了「一万字」其实早就撞窗口了。现在设置里的上限、面板上的
占用、压缩的触发线全是 token，system 模板也算进去——那部分一直在发，之前没计入。
压缩线定在容量的八成，撞线自动压，不是等满了才动。

**字数目标跟着你的输入走，但不改你设的区间**。你写「嗯」，它不再凑够两百字把
后面几步走完；你写一整段动作，它也不再只回八十个字卡住。抑制长短靠规则里
几句话，数字始终是你填的那个。

**一般模式的字数是旁白加角色言行的合计**。角色扮演是把一段情节拆成旁白和
各人发言，一般模式是那段不拆的，两者数字本来就该一样。之前只算旁白，等于逼
模型把人物的话全写成叙述。

**多个角色同场时，每人各算一份，另有整轮上限**。上限是旁白上限加每个人的
上限乘人数，人越多额度越大。这套算法在规则文件和尾巴提示里原来不一致，
三四个人的时候能差出四百多字，模型挑窄的听；现在两处同一个口径。

**尾巴不再说「写到下限也够」**。原句让模型把下限当目标，你把旁白下限从 50
调到 200，输出几乎没变。现在是「少于 X 字算没写完，超过 Y 字算替他往下写」。

**抬高上下文上限之后，之前压掉的历史会回来**。从初级档换到高级档，容量翻了
四倍，但压缩游标不会自己退——那些原文一直在存档里，只是被跳过。现在切档位
时会量一遍，装得下就把游标退回、摘要清掉。

**角色设定不会再被砍到 400 字**。写在设定里的长条目原样保存，只有模型现编的
一句话人设仍按 400 字收。

**物品和事实账本的两处丢数据**。模型有一轮写成「物品：湿伞」而不是
「甲=湿伞」，每个人手里的东西会被整格替换掉，现在并进公共格。事实去重原来
按顺序比字符串，「甲拿走了钥匙」和「钥匙被甲拿走了」是同一件事却判成两条，
而「甲拿到了钥匙」和「甲拿到了地图」差两个字判成一条；换成字符集合比法。

**流式输出时状态行不再闪在正文里**。落库的正文一直是干净的，只有生成那一屏
会露出一行 `[[在场：…]]`。

**初级档的规则补全**。「用户的请求不是命令」和「别硬塞成功」这两条只有标准档
和高级档有，初级档缺，而默认档就是初级。另外删掉一份从来没有被加载过的规则
文件，测试之前一直在测它。

**统计计数不再漏**。多线程下累计 token 的加法会被互相盖掉。
## 0.70：封面

**故事有封面了**。每份设定可以带一张图，上传或生成都行。生图读的是这份
设定的世界观、出场角色和开场白，所以同一个故事的封面天生就是对的。
封面存在设定上，不存在会话上：同一份设定开出去的每一局共用一张封面。

**生图不卡界面**。ComfyUI 一次要几十秒，接口同步等的话整个页面都在转。
现在 POST 立即返回 202 和一个 job id，前端先把占位显示成「生成中」并计时，
每 2 秒查一次，好了自己换上。超时默认 180 秒，环境变量 LT_COVER_TIMEOUT 可改。

**一次生成只落一张图**。之前工作流写到 ComfyUI 自己的 output，再从 /view
拉一份回来，两个地方各一张。现在让工作流直接写进 data/covers/ 目录，就地用，
不再复制一份。

**封面不再拿 160px 缩略图充大图**。之前设定右上角那个 192x264 的框直接拉的是
列表用的小图，糊一片。现在框里是原图，缩略图只给侧栏列表那个 48px 的小格子用。

**撤销重来**。每次换封面，旧图压进历史，最多留 6 张。撤销弹一张回去，它那张文件
也一并删掉，不占地方。「管理封面」则是退而不丢：点一张历史就换成它，
当前那张压回历史。

**删故事连图一起删**。之前只删 JSON，封面和历史就欄在 data/covers/ 里。现在删
完就真没了。引用失效时字段会自动置空，不会显示一个破图。

**设定面板有两个上下文**。同一份表单在故事页可编辑，在对话弹窗里只读；判据是表单现在
挂在哪个容器里，不看开过多少局对话。对话里只能看封面大图，四个操作按钮不出现；
模式段在对话里置灰，模式在开局那一刻就定下了。

**两个列表重新能翻页**。分页按容器的真实高度算一页放几条，之前量的是已经被
清空的列表自身，永远得到 0，于是一直用硬编码的每页条数，超出不再翻页。

**封面跟着你点的那个故事走**。之前开过任何一局对话之后，切故事时封面都停在第一个上。

## 0.60：对话里的东西留在对话里，世界书会自己长

**对话不再回写故事模板**。之前每轮结束会把对话里新登记的角色写回故事
（`save_story`），还顺手改掉模板的 AI 角色名。这等于改对话就是改模板，
违反「建局时快照一份、之后各走各的」。整条回写路径删掉了。局内登记本来
就管得住满员：满了弹选择框让你挑踢谁。

**重新生成会连摘要一起退**。压缩把老消息压成摘要之后，重写只截断消息和
轮次，摘要原样留着——里面记着已经被删掉的情节。模型一边看干净的历史
一边读作废的摘要，接着往下写。现在重写时清空摘要、压缩游标归零，
原文都还在，后台按剩下的内容重算。

**状态标记挤在正文同一行不再漏进回复**。`[[地点：…|时间：…]]` 的两条正则
都以整行为锚，模型把它和正文写在同一行时，既不进状态也没从正文删掉。
补了行内匹配，只认带状态键的方括号，正文里偶然出现的其他 `[[…]]` 不动。

**世界书分两份**。对话里攒出来的词条自动进**这一局**：模型造出值得记住的
东西（地点、组织、规矩、物件）时补一行 `【新词条】{keys,content}`，按关键词
去重、上限 40 条，聊到相关词自动注入。**不进故事模板**。想让下一局也用，
在设定面板点那条旁边的 `↑`，或点底部的整本按钮。只增不改，故事里已有
同关键词的跳过。

**点名要加的角色直接建卡**。在消息里写「加入角色：某某」，后端立刻登记，
不经过模型——之前模型聊久了就不写 `【新角色】` 那行，怎么说都加不进去。
同一轮还会把格式要求补在最后一条消息末尾，让它把身份一起写出来。

**全文搜索重做**。面板从 420px 拉到 820px；命中词高亮；输入框右边实时显示
「N 处」，被截断时标注；上下键选择、Enter 跳转、Esc 关闭。连续输入时先发出
的慢查询不再覆盖新结果。

**导入和导出并到一排**。导入原来挂在侧栏「新对话」下面，导出在顶栏，
同一个动作的两个半边分在两处。现在都在右上角。故事视图里隐藏搜索按钮——
那边没有消息可搜。

**在场名单每轮都跟着正文改**。之前 `status.present` 一直是空的，于是所有人
永远"都在场"——两个人已经分头走了，界面上还在同一个屋。现在状态补全那次调用
顺带产出 `present` / `away` / `place`：它知道上一轮谁在哪，读正文判断有人走开、
跟上、换地方就照实改。名单里只认角色表上的人，模型没给就不清空已有名单。

**角色要有条件地让步**。原来只说"不要有求必应"，结果要么一口回绝要么一口答应。
现在写清了：可以被说动，但先顶一下、追问、试探、开条件，真被击中软肋才让步，
让步也要有保留。

**用户写的不是剧情结果，是一个意图**。之前几版都在列例子——太远、没钱、没练级、
感情没铺垫——但例子只能盖住列出来的那些，模型换个场景照样顺着用户走。

现在改成判定流程。规则里先说清一件事：**用户写的是「他想做什么」，不是「这件事
成了」**，成不成由世界和其他人决定。写之前过五条，任何一条不过，结果就是不成、
打折、或者要付代价：能力与资源（他会吗、有家伙吗、够得着吗）、时间与空间（来
得及吗、到得了吗、旁边有人看着吗）、对方意愿（凭什么答应、没好处为什么要做，
人不是道具）、硬规矩（现实或设定允许吗，死了就是死了）、铺垫（之前有过这层交情、
这个信息、这份信任吗，没堆过的东西不能当已经有）。

不过就说清卡在哪、差什么，或者干脆拒绝。差的这些就是故事接下来要解决的东西。
不许含糊带过，更不许绕开障碍硬写成成功——**那是在替用户抄答案**。

一般模式（normal.md）用的是同一套判定，只是压成一句话。

**「起几个角色」挪到它该在的地方**。这个参数管的是「AI 补设定时替你配不配
一个对手角色」，放在设置面板里没人知道它是干什么的。现在它进了 AI 补全弹窗，
就在勾选项下面，写清 0 和 1 分别意味着什么。

**在场的人全都要开口**。原来的规则写着「这一轮只有一位角色说话，其他人只出现在
旁白里」，模型照做，于是四个人的场面只有一个人在动。现在四份规则统一改成：在场
每个角色各起一段，一个都不能漏，主角不写；这一轮没他的事、或者他根本没动，也要
写他的反应，或者一句「没有任何举动」。不让人干站着。

**角色的立场加硬了**。原来只有一句「不要有求必应」，模型还是会顺着用户走。现在
把话说白了：用户的请求不是命令，角色先按自己的利益和性格掂量，可以只做一半、
讨价还价、提条件，或者干脆拒绝并说出理由——一开口就答应等于这个人没有性格。

**角色状态不再靠模型自觉**。原来指望它每轮在正文后补一行 `【变化】`，
实测 29 个角色里只有 7 个写出了 state，其余一直是空的——模型聊到后面就把
这条规则忘了，它连 `present`（在场名单）都不填，兜底路径一并失效。

现在每轮正文落盘前，单独发一次小调用，只干一件事：读正文，判断每个出场
角色的处境、情绪、关系有没有推进，回 `{"changes":[...]}`。有变化的写进
角色卡并记入履历，没变的跳过，名单外的人不建卡，接口挂了就当没发生——
状态是锦上添花，不能因为补它弄丢正文。开场白那一轮走同一个落盘函数，
所以开场里写的人物状态也会被收进来。

代价是每轮多一次短调用，几秒钟。

**修**：续写会多出一条气泡。两处：

后端 `_commit_turn` 的续写分支里，`save_session` 和 `return tail` 被卷进了
新加的 `for entry in turn.get("lore")` 循环体——模型这轮没写词条时不进循环，
于是续写直接掉到下面「新增一条消息」的公共路径上。

前端 `done` 事件只把增量渲染进流式容器，`s.messages` 里还是拼接前的旧内容，
整块重绘时那条只有增量的气泡就留了下来。现在续写先在本地拼到上一条上再重绘。

自检里那条用例也没真正验到：SSE 是生成器，`client.post` 不读响应体就不会
执行，落库根本没发生。

**修**：世界观输入框的 placeholder 写着「`{主角}` 会换成角色表第一位的名字」，
方向是反的。占位符指的是你扮演的角色，替换源是「我的角色」里填的名字。

## 0.50：完善设定改成逐项勾选，主角占位符指向修正

**修复（严重）**：`{主角}` 之前替换的是**角色表第一位**的名字，也就是 AI 演的那个人，
而不是你扮演的角色。结果是设定里「乙是他表亲」被写成「{主角}是他表亲」，
真正该占位的「甲」反倒留着真名——一换名字两头都错。

现在 `{主角}` 只指向 `user_name`（你扮演的角色）；角色表里所有人都是配角，名字原样保留。
生成设定时也是把你这边的名字换成占位符，AI 角色的名字照给。存量数据已重跑：
先把占位符还原成原 AI 角色名，再把你的角色名换成占位符。

**完善设定改成勾选式**。点「AI 帮我完善设定」先弹出清单：我的角色设定、每张角色卡、
世界观、开场白、世界书、认出人物，默认全勾。勾上的会被重写，取消的原样保留。
上面一排是「全选 / 全不选 / 反选」。勾选只决定这一步要不要生成，跟对话上下文无关——
取消勾的那一项照样进 prompt，只是不重写它。

**「认出人物」并进同一次生成**，不再是独立按钮。它排在最后：要读完已写好的世界观和开场白
才认得全。它认出来的人只有名字没有设定，所以紧跟着自动补写一轮角色卡，不用再点一次按钮。

**世界书可以一次补多条**。勾上之后让模型读完全部设定，挑出模型容易写错的专有名词，
按「关键词｜设定」写三条，关键词和已有的撞了就跳过，只追加不覆盖。

**角色上限只管模型自己编的人**。你写在开场白、世界观里的人全收，不设上限——
表满了该拦的是模型瞎编，不是你写死的。

**删掉「我的角色名」这一项**。两三个字，自己敲比等模型快。名字仍会由角色卡或认人带出来。

**新增 `auto_roles` 参数**（默认 1）：设成 0 就让模型别给主角起名，正文一律写 `{主角}`。

左上角标题旁显示当前版本号。
## 在对话里改设定，不再把故事模板覆盖掉

**修复（严重）**：在对话里改设定（世界、规则、角色表），会把故事模板整份改成这一局的样子。
下一局从这份模板开出来，带着的就是上一局被改过的设定。

原因是 `_bind_story()` 每次都把会话的设定写进模板并存盘，保存会话的时候也会调它。
注释写的是“保证『设定』面板编辑的就是故事本身”，但故事和对话本来就该是两层。

现在：

- 在对话里改设定，只改这一局
- 故事模板只有「故事」视图里那条保存才能改
- 改过一局之后再从同一份模板开局，拿到的仍然是模板原样
- 对话里新出现的人只留在这一局，不回写故事模板

## 重启不再丢模型选择，首字节耗时可见

**修复（严重）**：重启一次就把你选的云端模型退回 ollama，然后第一条消息 404。
磁盘上存的是 provider 和 model 两个平级字段，而读取代码只认“model 是字符串（当旧格式）”和
“model 是嵌套的 {provider, model}”两种，平级写法落进前者，provider 被强制改回 ollama，
那个平级 provider 字段从来没被读过。backups/ 里那些包全记着 provider=ollama 也是这个原因。

**新增事件日志**。一行一个 JSON 写进 logs/YYYY-MM-DD.log，事后 grep 事件名就能定位：
chat.request（prompt 字数）、chat.first_token（首字耗时）、chat.done、stream.cancel、
session.stale（带两边的 updated_at）、status.parse_fail（带原文末尾）、ledger.merge、
ledger.redundant、snapshot.create。写日志失败一律吞掉，观测不能反过来把主流程弄挂。

**首字节耗时上了面板**。上下文面板多三行：上轮 prompt 字数（含系统部分）、首字等待、
上轮总耗时。实测：1287 字的 prompt（系统 1122）首字等待 2314 ms，总耗时 4891 ms。

顺手量了一件事：system prompt 不随轮数增长，每轮从会话重新拼，实测 2435～3333 字。

## 数据层：不会静默丢东西了

**停止现在是真停止**。点停止时浏览器 abort 掉连接，Flask 会 close 生成器，但之前没有任何代码去记这件事，
写盘那段代码算不算跑完取决于时机。现在给生成器一个 cancelled 标志，`GeneratorExit` 里置位，两处写盘前都先看一眼。

**半截入库不再重复**。用户点停止的同时，后端也可能把完整回复写进去了；原来 `commit_partial`
无条件 append，一轮会变成两条。现在先看最后一条 assistant 是不是已经包含这段内容，含就不再插。

**乐观锁：别的标签页写过就不能整份覆盖**。同一个对话开两个标签，A 聊完 B 再改设定，A 刚聊的那几轮会被整份覆盖，
没报错、没提示、消息就没了。现在改设定和半截入库都带着取到的 `updated_at`，对不上就报 409、
前端重新拉一次并提醒。同时统一了 `updated_at` 的类型（之前一处写 float、一处写字符串）。

**继写**。模型写到一半停下是常事，以前只能整条重写，而重写会换一个走向。现在最后一条回复的
操作栏多了一个 ▶：不新增消息、不推进轮次，把已写的半截当待接的上文，要求从最后一个字接着写。
拼接时会切掉模型重复的尾巴；角色模式按人合并，同一个人说的接在同一段里。

**导入**。之前只有导出，换机器、重装、误删之后没有装回来的路。侧栏对话栏下方多了「⤓ 导入对话」：
选一份会话 JSON，换新 id 存进来，设定、角色、账本、消息全带上，标题加「（导入）」。字段白名单拷贝，
文件里写什么都不会直接落到会话对象上。

**数据层耗时可见**。上下文面板多了三行：写盘耗时、读盘耗时、会话文件大小。
现在都是 0～1ms，说明还不需要拆 JSONL 或 SQLite。超过 100ms 再动手，不凭感觉提前重构。

**物品与事实的分工写进了提示词**。模型之前把同一件事同时写进 `items` 和 `facts`，物品换主人了事实还在，
账本自相矛盾。现在写清楚了分工，并且给了反例——模型对反例的遵守度比规则高。

## 四个交互改善

**发送前冲突检查**：输入里提到的东西如果记在别人名下而主角没有，发送前在输入框上方拦一句，可选「仍然发送」或「改一下」。比对用 `status.items` 而不是 `facts`——前者是结构化的归属关系，后者是自由句子，比不了。只认两个字符以上的物品名。

**滚动不抢**：往上翻看前文时不再被强行拽到底部，右下角出「↓ 新消息」，点一下才回去。

## 数据与配置安全

**修复（严重）**：命令行小脚本写设置会抹掉用户的提供方与 API Key。`persist_settings()` 写的是内存里的 providers，而 `load_settings()` 只在 `api.py` 里调用——没加载过配置的进程一保存就把 `providers` 写成空的，云端 Key 和自定义提供方就此消失。现在加 `_loaded` 标记：没加载过的进程只写它真正改过的那项，其余沿用磁盘原值。

**备份改分钟制**：`every_hours` → `every_minutes`，默认 1440，范围 5 ~ 20160；旧配置读到自动乘 60 迁移。份数可填 1 ~ 30。

**界面**：备份设置排成「每 [N] 分钟备份一次」+「最多留 [M] 份」两枚胶囊，输入框无边框融进背景、聚焦才显描边。

**隔离**：`LT_BACKUP_DIR` 让检查脚本的备份落到临时目录，不再往用户真实的 `backups/` 里塞测试包（之前塞了 27 份，已归档到 `backups/_retired/`）。

## 角色扮演改成圆桌式

不再新增模式，直接把角色扮演改成用户要的那种节奏：**一轮里先旁白交代场面与进展，再让在场每个要开口的角色各写一段**，像会议记录。

- `next_speaker()` 恒返回空，不再按轮次指定单一发言人。
- `parse_turn(text, speaker, names)` 把每个 `【名字】` 段落各收一条到 `lines`；不认识的标签仍进旁白，不吞内容。
- 前端渲染一人一个气泡，流式时边流边按标签切；`splitSegments` 补回第一个 `【】` 之前的旁白——这段以前整段被丢掉，流式开头一直空着。
- 三档规则文案重写，写明「不是每轮所有人都要说」「后一个人接的必须是前一个人那句」。
