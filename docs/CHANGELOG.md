# 更新记录

倒序。只记用户能感知的变化，内部重构略过。
## 0.90：字数按你说的算

**上下文改成按 token 计量**。原来面板和压缩线算的是字数，可模型吃的是 token，
两者差着一倍多；到了「一万字」其实早就撞窗口了。现在设置里的上限、面板上的
占用、压缩的触发线全是 token，system 模板也算进去——那部分一直在发，之前没计入。
压缩线定在容量的八成，撞线自动压，不是等满了才动。

**字数目标跟着你的输入走，但不改你设的区间**。你写「嗯」，它不再凑够两百字把
后面几步走完；你写一整段动作，它也不再只回八十个字卡住。抑制长短靠规则里
几句话，数字始终是你填的那个。

**一般模式的字数是旁白加角色言行的合计**。角色扮演是把一段情节拆成旁白和
各人发言，一般模式是那段不拆的，两者数字本来就该一样。之前只算旁白，等于逼
模型把人物的话全写成叙述。

**多个角色同场时，每人各算一份，另有整轮上限**。上限是旁白上限加每个人的
上限乘人数，人越多额度越大。这套算法在规则文件和尾巴提示里原来不一致，
三四个人的时候能差出四百多字，模型挑窄的听；现在两处同一个口径。

**尾巴不再说「写到下限也够」**。原句让模型把下限当目标，你把旁白下限从 50
调到 200，输出几乎没变。现在是「少于 X 字算没写完，超过 Y 字算替他往下写」。

**抬高上下文上限之后，之前压掉的历史会回来**。从初级档换到高级档，容量翻了
四倍，但压缩游标不会自己退——那些原文一直在存档里，只是被跳过。现在切档位
时会量一遍，装得下就把游标退回、摘要清掉。

**角色设定不会再被砍到 400 字**。写在设定里的长条目原样保存，只有模型现编的
一句话人设仍按 400 字收。

**物品和事实账本的两处丢数据**。模型有一轮写成「物品：湿伞」而不是
「甲=湿伞」，每个人手里的东西会被整格替换掉，现在并进公共格。事实去重原来
按顺序比字符串，「甲拿走了钥匙」和「钥匙被甲拿走了」是同一件事却判成两条，
而「甲拿到了钥匙」和「甲拿到了地图」差两个字判成一条；换成字符集合比法。

**流式输出时状态行不再闪在正文里**。落库的正文一直是干净的，只有生成那一屏
会露出一行 `[[在场：…]]`。

**初级档的规则补全**。「用户的请求不是命令」和「别硬塞成功」这两条只有标准档
和高级档有，初级档缺，而默认档就是初级。另外删掉一份从来没有被加载过的规则
文件，测试之前一直在测它。

**统计计数不再漏**。多线程下累计 token 的加法会被互相盖掉。
## 0.70：封面

**故事有封面了**。每份设定可以带一张图，上传或生成都行。生图读的是这份
设定的世界观、出场角色和开场白，所以同一个故事的封面天生就是对的。
封面存在设定上，不存在会话上：同一份设定开出去的每一局共用一张封面。

**生图不卡界面**。ComfyUI 一次要几十秒，接口同步等的话整个页面都在转。
现在 POST 立即返回 202 和一个 job id，前端先把占位显示成「生成中」并计时，
每 2 秒查一次，好了自己换上。超时默认 180 秒，环境变量 LT_COVER_TIMEOUT 可改。

**一次生成只落一张图**。之前工作流写到 ComfyUI 自己的 output，再从 /view
拉一份回来，两个地方各一张。现在让工作流直接写进 data/covers/ 目录，就地用，
不再复制一份。

**封面不再拿 160px 缩略图充大图**。之前设定右上角那个 192x264 的框直接拉的是
列表用的小图，糊一片。现在框里是原图，缩略图只给侧栏列表那个 48px 的小格子用。

**撤销重来**。每次换封面，旧图压进历史，最多留 6 张。撤销弹一张回去，它那张文件
也一并删掉，不占地方。「管理封面」则是退而不丢：点一张历史就换成它，
当前那张压回历史。

**删故事连图一起删**。之前只删 JSON，封面和历史就欄在 data/covers/ 里。现在删
完就真没了。引用失效时字段会自动置空，不会显示一个破图。

**设定面板有两个上下文**。同一份表单在故事页可编辑，在对话弹窗里只读；判据是表单现在
挂在哪个容器里，不看开过多少局对话。对话里只能看封面大图，四个操作按钮不出现；
模式段在对话里置灰，模式在开局那一刻就定下了。

**两个列表重新能翻页**。分页按容器的真实高度算一页放几条，之前量的是已经被
清空的列表自身，永远得到 0，于是一直用硬编码的每页条数，超出不再翻页。

**封面跟着你点的那个故事走**。之前开过任何一局对话之后，切故事时封面都停在第一个上。

## 0.60：对话里的东西留在对话里，世界书会自己长

**对话不再回写故事模板**。之前每轮结束会把对话里新登记的角色写回故事
（`save_story`），还顺手改掉模板的 AI 角色名。这等于改对话就是改模板，
违反「建局时快照一份、之后各走各的」。整条回写路径删掉了。局内登记本来
就管得住满员：满了弹选择框让你挑踢谁。

**重新生成会连摘要一起退**。压缩把老消息压成摘要之后，重写只截断消息和
轮次，摘要原样留着——里面记着已经被删掉的情节。模型一边看干净的历史
一边读作废的摘要，接着往下写。现在重写时清空摘要、压缩游标归零，
原文都还在，后台按剩下的内容重算。

**状态标记挤在正文同一行不再漏进回复**。`[[地点：…|时间：…]]` 的两条正则
都以整行为锚，模型把它和正文写在同一行时，既不进状态也没从正文删掉。
补了行内匹配，只认带状态键的方括号，正文里偶然出现的其他 `[[…]]` 不动。

**世界书分两份**。对话里攒出来的词条自动进**这一局**：模型造出值得记住的
东西（地点、组织、规矩、物件）时补一行 `【新词条】{keys,content}`，按关键词
去重、上限 40 条，聊到相关词自动注入。**不进故事模板**。想让下一局也用，
在设定面板点那条旁边的 `↑`，或点底部的整本按钮。只增不改，故事里已有
同关键词的跳过。

**点名要加的角色直接建卡**。在消息里写「加入角色：某某」，后端立刻登记，
不经过模型——之前模型聊久了就不写 `【新角色】` 那行，怎么说都加不进去。
同一轮还会把格式要求补在最后一条消息末尾，让它把身份一起写出来。

**全文搜索重做**。面板从 420px 拉到 820px；命中词高亮；输入框右边实时显示
「N 处」，被截断时标注；上下键选择、Enter 跳转、Esc 关闭。连续输入时先发出
的慢查询不再覆盖新结果。

**导入和导出并到一排**。导入原来挂在侧栏「新对话」下面，导出在顶栏，
同一个动作的两个半边分在两处。现在都在右上角。故事视图里隐藏搜索按钮——
那边没有消息可搜。

**在场名单每轮都跟着正文改**。之前 `status.present` 一直是空的，于是所有人
永远"都在场"——两个人已经分头走了，界面上还在同一个屋。现在状态补全那次调用
顺带产出 `present` / `away` / `place`：它知道上一轮谁在哪，读正文判断有人走开、
跟上、换地方就照实改。名单里只认角色表上的人，模型没给就不清空已有名单。

**角色要有条件地让步**。原来只说"不要有求必应"，结果要么一口回绝要么一口答应。
现在写清了：可以被说动，但先顶一下、追问、试探、开条件，真被击中软肋才让步，
让步也要有保留。

**用户写的不是剧情结果，是一个意图**。之前几版都在列例子——太远、没钱、没练级、
感情没铺垫——但例子只能盖住列出来的那些，模型换个场景照样顺着用户走。

现在改成判定流程。规则里先说清一件事：**用户写的是「他想做什么」，不是「这件事
成了」**，成不成由世界和其他人决定。写之前过五条，任何一条不过，结果就是不成、
打折、或者要付代价：能力与资源（他会吗、有家伙吗、够得着吗）、时间与空间（来
得及吗、到得了吗、旁边有人看着吗）、对方意愿（凭什么答应、没好处为什么要做，
人不是道具）、硬规矩（现实或设定允许吗，死了就是死了）、铺垫（之前有过这层交情、
这个信息、这份信任吗，没堆过的东西不能当已经有）。

不过就说清卡在哪、差什么，或者干脆拒绝。差的这些就是故事接下来要解决的东西。
不许含糊带过，更不许绕开障碍硬写成成功——**那是在替用户抄答案**。

一般模式（normal.md）用的是同一套判定，只是压成一句话。

**「起几个角色」挪到它该在的地方**。这个参数管的是「AI 补设定时替你配不配
一个对手角色」，放在设置面板里没人知道它是干什么的。现在它进了 AI 补全弹窗，
就在勾选项下面，写清 0 和 1 分别意味着什么。

**在场的人全都要开口**。原来的规则写着「这一轮只有一位角色说话，其他人只出现在
旁白里」，模型照做，于是四个人的场面只有一个人在动。现在四份规则统一改成：在场
每个角色各起一段，一个都不能漏，主角不写；这一轮没他的事、或者他根本没动，也要
写他的反应，或者一句「没有任何举动」。不让人干站着。

**角色的立场加硬了**。原来只有一句「不要有求必应」，模型还是会顺着用户走。现在
把话说白了：用户的请求不是命令，角色先按自己的利益和性格掂量，可以只做一半、
讨价还价、提条件，或者干脆拒绝并说出理由——一开口就答应等于这个人没有性格。

**角色状态不再靠模型自觉**。原来指望它每轮在正文后补一行 `【变化】`，
实测 29 个角色里只有 7 个写出了 state，其余一直是空的——模型聊到后面就把
这条规则忘了，它连 `present`（在场名单）都不填，兜底路径一并失效。

现在每轮正文落盘前，单独发一次小调用，只干一件事：读正文，判断每个出场
角色的处境、情绪、关系有没有推进，回 `{"changes":[...]}`。有变化的写进
角色卡并记入履历，没变的跳过，名单外的人不建卡，接口挂了就当没发生——
状态是锦上添花，不能因为补它弄丢正文。开场白那一轮走同一个落盘函数，
所以开场里写的人物状态也会被收进来。

代价是每轮多一次短调用，几秒钟。

**修**：续写会多出一条气泡。两处：

后端 `_commit_turn` 的续写分支里，`save_session` 和 `return tail` 被卷进了
新加的 `for entry in turn.get("lore")` 循环体——模型这轮没写词条时不进循环，
于是续写直接掉到下面「新增一条消息」的公共路径上。

前端 `done` 事件只把增量渲染进流式容器，`s.messages` 里还是拼接前的旧内容，
整块重绘时那条只有增量的气泡就留了下来。现在续写先在本地拼到上一条上再重绘。

自检里那条用例也没真正验到：SSE 是生成器，`client.post` 不读响应体就不会
执行，落库根本没发生。

**修**：世界观输入框的 placeholder 写着「`{主角}` 会换成角色表第一位的名字」，
方向是反的。占位符指的是你扮演的角色，替换源是「我的角色」里填的名字。

## 0.50：完善设定改成逐项勾选，主角占位符指向修正

**修复（严重）**：`{主角}` 之前替换的是**角色表第一位**的名字，也就是 AI 演的那个人，
而不是你扮演的角色。结果是设定里「乙是他表亲」被写成「{主角}是他表亲」，
真正该占位的「甲」反倒留着真名——一换名字两头都错。

现在 `{主角}` 只指向 `user_name`（你扮演的角色）；角色表里所有人都是配角，名字原样保留。
生成设定时也是把你这边的名字换成占位符，AI 角色的名字照给。存量数据已重跑：
先把占位符还原成原 AI 角色名，再把你的角色名换成占位符。

**完善设定改成勾选式**。点「AI 帮我完善设定」先弹出清单：我的角色设定、每张角色卡、
世界观、开场白、世界书、认出人物，默认全勾。勾上的会被重写，取消的原样保留。
上面一排是「全选 / 全不选 / 反选」。勾选只决定这一步要不要生成，跟对话上下文无关——
取消勾的那一项照样进 prompt，只是不重写它。

**「认出人物」并进同一次生成**，不再是独立按钮。它排在最后：要读完已写好的世界观和开场白
才认得全。它认出来的人只有名字没有设定，所以紧跟着自动补写一轮角色卡，不用再点一次按钮。

**世界书可以一次补多条**。勾上之后让模型读完全部设定，挑出模型容易写错的专有名词，
按「关键词｜设定」写三条，关键词和已有的撞了就跳过，只追加不覆盖。

**角色上限只管模型自己编的人**。你写在开场白、世界观里的人全收，不设上限——
表满了该拦的是模型瞎编，不是你写死的。

**删掉「我的角色名」这一项**。两三个字，自己敲比等模型快。名字仍会由角色卡或认人带出来。

**新增 `auto_roles` 参数**（默认 1）：设成 0 就让模型别给主角起名，正文一律写 `{主角}`。

左上角标题旁显示当前版本号。
## 在对话里改设定，不再把故事模板覆盖掉

**修复（严重）**：在对话里改设定（世界、规则、角色表），会把故事模板整份改成这一局的样子。
下一局从这份模板开出来，带着的就是上一局被改过的设定。

原因是 `_bind_story()` 每次都把会话的设定写进模板并存盘，保存会话的时候也会调它。
注释写的是“保证『设定』面板编辑的就是故事本身”，但故事和对话本来就该是两层。

现在：

- 在对话里改设定，只改这一局
- 故事模板只有「故事」视图里那条保存才能改
- 改过一局之后再从同一份模板开局，拿到的仍然是模板原样
- 对话里新出现的人只留在这一局，不回写故事模板

## 重启不再丢模型选择，首字节耗时可见

**修复（严重）**：重启一次就把你选的云端模型退回 ollama，然后第一条消息 404。
磁盘上存的是 provider 和 model 两个平级字段，而读取代码只认“model 是字符串（当旧格式）”和
“model 是嵌套的 {provider, model}”两种，平级写法落进前者，provider 被强制改回 ollama，
那个平级 provider 字段从来没被读过。backups/ 里那些包全记着 provider=ollama 也是这个原因。

**新增事件日志**。一行一个 JSON 写进 logs/YYYY-MM-DD.log，事后 grep 事件名就能定位：
chat.request（prompt 字数）、chat.first_token（首字耗时）、chat.done、stream.cancel、
session.stale（带两边的 updated_at）、status.parse_fail（带原文末尾）、ledger.merge、
ledger.redundant、snapshot.create。写日志失败一律吞掉，观测不能反过来把主流程弄挂。

**首字节耗时上了面板**。上下文面板多三行：上轮 prompt 字数（含系统部分）、首字等待、
上轮总耗时。实测：1287 字的 prompt（系统 1122）首字等待 2314 ms，总耗时 4891 ms。

顺手量了一件事：system prompt 不随轮数增长，每轮从会话重新拼，实测 2435～3333 字。

## 数据层：不会静默丢东西了

**停止现在是真停止**。点停止时浏览器 abort 掉连接，Flask 会 close 生成器，但之前没有任何代码去记这件事，
写盘那段代码算不算跑完取决于时机。现在给生成器一个 cancelled 标志，`GeneratorExit` 里置位，两处写盘前都先看一眼。

**半截入库不再重复**。用户点停止的同时，后端也可能把完整回复写进去了；原来 `commit_partial`
无条件 append，一轮会变成两条。现在先看最后一条 assistant 是不是已经包含这段内容，含就不再插。

**乐观锁：别的标签页写过就不能整份覆盖**。同一个对话开两个标签，A 聊完 B 再改设定，A 刚聊的那几轮会被整份覆盖，
没报错、没提示、消息就没了。现在改设定和半截入库都带着取到的 `updated_at`，对不上就报 409、
前端重新拉一次并提醒。同时统一了 `updated_at` 的类型（之前一处写 float、一处写字符串）。

**继写**。模型写到一半停下是常事，以前只能整条重写，而重写会换一个走向。现在最后一条回复的
操作栏多了一个 ▶：不新增消息、不推进轮次，把已写的半截当待接的上文，要求从最后一个字接着写。
拼接时会切掉模型重复的尾巴；角色模式按人合并，同一个人说的接在同一段里。

**导入**。之前只有导出，换机器、重装、误删之后没有装回来的路。侧栏对话栏下方多了「⤓ 导入对话」：
选一份会话 JSON，换新 id 存进来，设定、角色、账本、消息全带上，标题加「（导入）」。字段白名单拷贝，
文件里写什么都不会直接落到会话对象上。

**数据层耗时可见**。上下文面板多了三行：写盘耗时、读盘耗时、会话文件大小。
现在都是 0～1ms，说明还不需要拆 JSONL 或 SQLite。超过 100ms 再动手，不凭感觉提前重构。

## 四个交互改善

**发送前冲突检查**：输入里提到的东西如果记在别人名下而主角没有，发送前在输入框上方拦一句，可选「仍然发送」或「改一下」。比对用 `status.items` 而不是 `facts`——前者是结构化的归属关系，后者是自由句子，比不了。只认两个字符以上的物品名。

**输入草稿**：切会话、刷新、开新会话，写了一半的话还在。按会话 id 存 localStorage，debounce 500ms 写，进会话读回。只在 input 事件里存——切会话时 `syncComposer` 会被调用，那一刻输入框里还是上一局的字，跟着存会串味。

**滚动不抢**：往上翻看前文时不再被强行拽到底部，右下角出「↓ 新消息」，点一下才回去。

**全文搜索**：顶栏 🔍，扫所有会话的正文、旁白和台词，给会话名、轮次和片段，点结果跳过去并高亮。

## 数据与配置安全

**修复（严重）**：命令行小脚本写设置会抹掉用户的提供方与 API Key。`persist_settings()` 写的是内存里的 providers，而 `load_settings()` 只在 `api.py` 里调用——没加载过配置的进程一保存就把 `providers` 写成空的，云端 Key 和自定义提供方就此消失。现在加 `_loaded` 标记：没加载过的进程只写它真正改过的那项，其余沿用磁盘原值。

**备份改分钟制**：`every_hours` → `every_minutes`，默认 1440，范围 5 ~ 20160；旧配置读到自动乘 60 迁移。份数可填 1 ~ 30。

**界面**：备份设置排成「每 [N] 分钟备份一次」+「最多留 [M] 份」两枚胶囊，输入框无边框融进背景、聚焦才显描边。

**隔离**：`LT_BACKUP_DIR` 让检查脚本的备份落到临时目录，不再往用户真实的 `backups/` 里塞测试包（之前塞了 27 份，已归档到 `backups/_retired/`）。

## 角色扮演改成圆桌式

不再新增模式，直接把角色扮演改成用户要的那种节奏：**一轮里先旁白交代场面与进展，再让在场每个要开口的角色各写一段**，像会议记录。

- `next_speaker()` 恒返回空，不再按轮次指定单一发言人。
- `parse_turn(text, speaker, names)` 把每个 `【名字】` 段落各收一条到 `lines`；不认识的标签仍进旁白，不吞内容。
- 前端渲染一人一个气泡，流式时边流边按标签切；`splitSegments` 补回第一个 `【】` 之前的旁白——这段以前整段被丢掉，流式开头一直空着。
- 三档规则文案重写，写明「不是每轮所有人都要说」「后一个人接的必须是前一个人那句」。
