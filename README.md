# 灵枢

本地跑的长篇角色扮演写作工具。故事设定和对话分离：故事是模板，同一个故事可以开无数局对话，每局都会继承设定并各自演化。

后端 Flask，前端原生 ES modules，**没有构建步骤**：改一行 CSS 刷新页面就生效。

## 快速开始

需要一个跑得动的模型。默认走本地 Ollama：

```bash
ollama serve
ollama pull dmtx/qwen3.5-9b-abliterated
```

然后：

```bash
pip install -r requirements.txt
python lt.py
```

打开 http://127.0.0.1:5000 。换端口用环境变量：`PORT=8080 python lt.py`。

连云端也行：设置里填 OpenAI 兼容的 base_url 和 Key，DeepSeek 填 `https://api.deepseek.com/v1` + `deepseek-chat`。

自检（不发网络请求，几十秒）：

```bash
python check.py
```

## 用它做什么

左边是两栏：**故事**和**对话**。故事是原始模板（角色、世界观、开场白），点「用这份设定再开一局」在同一个人设上开新对话。故事改了不影响已经开始的对话，只会把新角色回流进去。

对话里按 `Enter` 发送，`Shift+Enter` 换行。每条 AI 回复可以重写、就地编辑、从这条分叉出一条新时间线。刷新页面会回到你上次待的那一页、那个对话。

正文和历史都会自动压缩；聊久了超出上下文限制时，早期的内容会被压成摘要，不需要手动清。

## 两种模式

**一般模式**：AI 是叙述者，用第三人称写场景、动作和在场角色的反应，不替你演。

**角色扮演模式**：AI 戴上一张具体的角色卡，只演那一个角色。谁说话由代码分配（按轮次在在场角色里轮转），模型没法让配角抢戏。

模式固定在每个会话上，故事里可以预设，开新局之后还能改。

## 数据在哪

全部在 `data/` 下，纯 JSON，可以直接看、直接备份、直接拷走：

```
data/
├── <会话 id>.json          一局对话（消息、角色、状态、账本、摘要）
├── stories/<故事 id>.json   故事模板
├── snapshots/<会话 id>/     每 15 轮和改设定前的存档点，保留 10 份
└── settings.json          模型、Key、写作参数、档位（含明文 API Key，别外传）
```

侧栏「⛁」可以把整个 `data/` 打成 zip 存到 `backups/`，打包时会把 `settings.json` 里的 API Key 清空，所以导出的包可以放心挪走。支持定时备份。

## 已知限制

长对话的一致性靠状态行和事实账本撑着，而这两样都要模型主动写。9B 级别的模型大约三分之二的轮次能写全，写作质量还过得去；换更强的模型时记得在设置里把「模型能力档位」调高，会切换成更完整的结构化格式。

角色进出场景由模型判断并写进状态行。你明确说「让他出去」时，小模型有时不会照做——这属于模型理解力，不是状态机制的问题。

没有多用户、没有鉴权。它设计成只在你自己的机器上跑。
