# 代面

当前版本 **1.00**。

本地跑的长篇角色扮演写作工具。故事设定和对话分离：故事是模板，同一个故事可以开无数局对话，每局继承设定并各自演化。

后端 Flask，前端原生 ES modules，**没有构建步骤**：改一行 CSS 刷新页面就生效。数据全在本地 JSON 文件里，没有数据库。

## 快速开始

需要一个跑得动的模型。默认走本地 Ollama：

```bash
ollama serve
ollama pull dmtx/qwen3.5-9b-abliterated
```

然后起服务。Windows 一键起（自动建 `.venv`、装依赖，都齐了就直接起）：

```powershell
.\start.ps1
```

头一次跑如果提示脚本被禁止执行，套一层：

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

常用参数：`-Port 5001` 换端口，`-Stop` 先干掉占着端口的旧进程，`-Reinstall` 强制重装依赖。

不想用脚本就手动来：

```bash
pip install -r requirements.txt
python lt.py
```

打开 http://127.0.0.1:5000 。换端口用环境变量，PowerShell 写法：

```powershell
$env:PORT=8080; python lt.py
```

cmd 写法是 `set PORT=8080 && python lt.py`。

连云端也行：设置 → 模型里填 OpenAI 兼容的 base_url 和 Key。DeepSeek 填 `https://api.deepseek.com/v1` + `deepseek-chat`，两者都是 OpenAI 兼容协议，不需要额外代码。

自检（不发网络请求，几十秒）：

```bash
python check.py
```

## 怎么用

左边两栏：**故事**和**对话**。故事是原始模板（角色、世界观、开场白），点「用这份设定再开一局」在同一个人设上开新对话。故事改了不影响已经开始的对话，只会把新角色回流进去。

对话里按 `Enter` 发送，`Shift+Enter` 换行。每条 AI 回复可以重写、就地编辑、从这条分叉出一条新时间线。刷新页面会回到上次待的那一页、那个对话。

顶栏那一行是当前局面：`主角：甲　在场：乙、丙　不在场：丁`。点任意一个名字弹出这个角色此刻的状况、物品和最近发过的话。

正文和历史会自动压缩；聊久了超出上下文限制时，早期内容被压成摘要，不需要手动清。

## 两种模式

**一般模式**：AI 是叙述者，用第三人称写场景、动作和在场角色的反应，不替你演。

**角色扮演模式**：AI 先写一段旁白交代场面与进展，然后**在场每个要开口的角色各写一段**，像会议记录那样一轮里连着几个人说话。具体谁开口由模型按剧情决定，退场的人不会插话。

模式固定在每个会话上，故事里可以预设，开新局之后还能改。

## 已经做进去的东西

- **发送前冲突检查**：输入里提到的东西如果账本记在别人名下（而你自己这没有），发送前在输入框上方拦一句，可以选「仍然发送」或「改一下」。
- **输入草稿**：写了一半切走、刷新、开新会话，回来还在。按会话分别存，发送成功即清除。
- **滚动不抢**：往上翻看前文时新内容不会把你拽到底部，右下角出「↓ 新消息」，点一下才回去。
- **全文搜索**：顶栏 🔍，扫所有会话的正文、旁白和每段台词，给会话名、第几轮、上下文片段，点结果直接跳过去。
- **备份**：设置 → 备份，可手动打包 `data/`，也可定时（分钟级）自动备份，份数自选。包里的 API Key 会被抹掉，可以放心挪走。
- **续写**：模型写到一半停了，最后一条回复的操作栏有个 ▶，从停下的那个字接着写，
  不重新开头。
- **导入导出**：顶栏导出 Markdown；侧栏「⤓ 导入对话」把导出的会话 JSON 装回来，换机器不丢。
- **数据层耗时**：上下文面板里直接看写盘、读盘耗时和会话文件大小，超过 100ms 再考虑拆数据层。
- **存档点**：每 15 轮和每次改设定前自动存一份，可回滚。
- **封面图**：故事设定右上角那个框。可以上传一张，也可以让它按这份设定的世界观和出场角色
  自动生图（默认连本机 ComfyUI）。生图走后台任务，不卡界面；不满意可以一步步撤。
  每份设定记最近 6 张，「管理封面」里点一张就换成它，不要的删掉。
  列表和标题旁都是另存的 160px 小图，不拉原图。

## 数据在哪

全部在 `data/` 下，纯 JSON，可以直接看、直接备份、直接拷走：

```
data/
├── <会话 id>.json           一局对话（消息、角色、状态、账本、摘要）
├── stories/<故事 id>.json    故事模板
├── snapshots/<会话 id>/      存档点，每个会话留最近 10 份
├── covers/                   封面原图
│   └── thumbs/               160px 缩略图，列表用
└── settings.json           模型、Key、写作参数、档位（含明文 API Key，别外传）
```

## 已知限制

长对话的一致性靠状态行和事实账本撑着，而这两样都要模型主动写。9B 级别的模型大约三分之二的轮次能写全。换更强的模型时记得在设置里把「模型能力档位」调高，会切换成更完整的结构化格式。

角色进出场景由模型判断并写进状态行。你明确说「让他出去」时，小模型有时不会照做——这属于模型理解力，不是状态机制的问题。新人物也一样：它必须被写进「在场」名单或者打上 `【新角色】`，后端才认得出这个名字；只出现在散文里的「己」不会被自动注册。

封面生图需要本机跑着 ComfyUI（默认 127.0.0.1:8188），且它要能写进本项目的
data/covers/ 目录。跑在另一台机器上时生图会失败，上传照旧可用。

没有多用户、没有鉴权。它设计成只在你自己的机器上跑。
